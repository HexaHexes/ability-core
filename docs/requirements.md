# Requirements inventory - Tensura RPG ability ecosystem

Single source of truth for requirement traceability across the ecosystem
repositories. One row per requirement. This document is generated by hand from
the project brief and is reconciled against the actual issue state - when a
requirement's issues change, this table changes in the same PR.

The roadmap itself is not a document: it is the set of GitHub **milestones**
("Phase N - ...") in each repository, whose progress is computed from the
assigned issues. The `Milestone` column below matches those milestone titles
one-to-one.

**Status vocabulary** (never skipped forward):

- `awaiting-spike` - blocked on an open investigation issue
- `awaiting-design` - researched, design not yet selected/approved
- `designed` - approach selected and documented, not yet ready to code
- `ready` - passed the readiness gate (scope, evidence, AC, approach, deps, risks, tests)
- `implemented` / `tested` / `released` - as the words say

**Type**: F = feature, B = bug, I = investigation, D = documentation.
**Priority**: P0 = critical blocker for other work; P1 = high; P2 = normal; P3 = low/stretch.

The owning repository files the issues for each requirement; "Depends" lists
requirement IDs or spikes that gate it. Acceptance criteria and test plans are
written into the implementation issues; this table records that they exist.
